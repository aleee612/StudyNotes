> [!warning]+ 做题须知
> 区分两种 MB：
> 
> **二进制容量单位**：
   严格写法是 $1\,\mathrm{MiB}=2^{20}$ Byte；考研计组题常把内存容量中的“1 MB”按 $2^{20}$ Byte 处理，尤其是 MAR、芯片扩展题
   >
   **数据传输速率的 MB（十进制）**：
   $1\,\mathrm{MB}=10^{6}$ Byte = 1,000,000 Byte
   常用于 **硬盘厂商标称容量、带宽、硬盘标称速度和网络速度**
   Mbps、MB/s 里往往默认十进制（工程计量单位）

> [!note] 服务访问点
>数据链路层向网络层分用：帧的“类型”字段
>网络层向传输层分用：IPv4 的“协议”字段或 IPv6 的“下一个首部”字段
>传输层向应用进程分用：端口号
>应用层通过应用协议/API 为用户或应用进程提供服务；“用户界面”不是各应用层协议统一具有的首部字段

> [!warning] 常用首部长度
> 以太网帧：首部 14B，尾部 FCS 4B；二者合计开销 18B（FCS 不属于首部）
> IPv4：首部最小 20B，最大 60B；IPv6 基本首部固定 40B
> TCP：首部最小 20B，最大 60B
> UDP：8B

### 数据链路层
#### 主要功能
1. 帧定界（定义数据格式）
2. 差错**检测** & **纠错** 
3. 流量控制（协调相邻发送方与接收方的速率）不是拥塞控制；拥塞控制面向整个网络，经典 TCP 主要在传输层实现，网络层也可通过丢包、显式通知等机制参与。
4. 透明传输：通过字符填充或比特填充，使数据中与帧定界符相同的内容不会被误判；不是“主要体现在交换机”
5. 可按具体协议提供可靠传输（如使用确认与重传）；以太网数据链路层通常不保证可靠交付

### 网络层
#### 主要功能
1. 提供**主机到主机**的逻辑通信（不要与数据链路层相邻结点间的“点到点”通信混淆）
2. 提供不可靠服务
3. IPv4 首部校验和只检测首部；IPv6 基本首部不含首部校验和。端到端数据差错检测由 TCP/UDP 等上层协议负责。

###### 各设备的处理层次
> 设备速度取决于硬件实现、端口速率和负载，不能仅按工作层次排出固定的“快慢顺序”。

| 设备            | 工作层次  | 主要处理依据 |
| ------------- | ----- | -------- |
| 集线器（Hub）      | 物理层   | 比特信号，不进行选择转发 |
| 网桥（Bridge）    | 数据链路层 | MAC 地址 |
| 二层交换机（Switch） | 数据链路层 | MAC 地址表 |
| 路由器（Router）   | 网络层   | IP 地址、路由表 |
| 网关（Gateway）   | 视具体类型而定 | 协议或应用层转换 |
### 传输层
#### 主要功能
1. 提供主机间**进程**（端到端）的逻辑通信
2. 能提供可靠的服务
3. 复用和分用：
	复用：发送方，多个应用进程可使用同一个传输层协议传送数据
	分用：接收方，剥去报文首部后，能将数据正确交付给对应的目的应用进程 
4. 差错检测
	TCP/UDP 校验和覆盖报文段（并结合伪首部）；校验失败的报文段会被丢弃。TCP 可通过序号、确认与超时等机制触发重传，UDP 本身不提供重传
5. 提供面向连接和无连接的服务
