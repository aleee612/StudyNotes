> [[TCP拥塞控制#1. 慢开始（慢启动）]] **A** ![[Pasted image 20260724143641.png]]
1. TCP 的发送窗口由 **发送窗口 = min(cwnd, rwnd)** 决定
2. `t₀` 时刻：
    1. `cwnd = 2000B`，`rwnd ≥ 2000B`
    2. 所以发送窗口 = `2000B`
    3. MSS = `1000B`
    4. 因此甲连续发送 **2 个 TCP 段**（`seq=2001`、`seq=3001`）
3. `t₁` 时刻收到确认段：
    1. `ack_seq = 3001`
    2. 表示 **第一个 TCP 段（1000B）已确认收到**
    3. 第二个 TCP 段（`seq=3001`）**仍未确认**
    4. 当前未确认数据量（Flight Size）为 **1000B**
4. 此时：
    1. `cwnd = 2000B`，`ssthresh = 8000B`
    2. 因为 `cwnd < ssthresh`，仍处于**慢开始阶段**
    3. **收到一个新的 ACK，cwnd 增加 1 MSS**
    4. 所以：  $cwnd=2000+1000=3000B$ 
5. 接收方通告：
    1. `rwnd = 4000B`
    2. 因此新的发送窗口为：  
        $\min(cwnd,rwnd)=\min(3000,4000)=3000B$ 
6. 已有未确认数据 **1000B**，因此还能继续发送：  
    $3000-1000=2000B$ 
7. MSS = `1000B`，所以还能发送：  
    $2000/1000=2\text{ 段}$ 
> [!note]- 为什么不是 3 段？  
> 容易把**慢开始**理解成"收到 ACK 后窗口立即翻倍"
> 实际协议规定是：
> - **每收到一个新的 ACK，`cwnd += 1 MSS`**
> - **一个 RTT 内收到所有 ACK 时，整体效果才表现为窗口翻倍**
> 本题只收到 **1 个 ACK**，因此：
> ```
> cwnd：2 MSS → 3 MSS
> ```
> 而不是：
> ```
> 2 MSS → 4 MSS
> ```
> 此时发送窗口只有 **3000B**，其中已有 **1000B** 数据尚未确认，因此只能再发送：
> $3000-1000=2000B=2\text{ MSS}$
> > **还能发送的数据 = min(cwnd, rwnd) − 当前未确认的数据量**
