### 哈希函数
$$Hash(key)=Addr $$
或
$$H(key)=Addr$$
- 地址$Addr$可以是数组下标、索引或内存地址等
- **冲突**：散列函数将两个或两个以上不同的关键字映射到同一地址的现象
- **同义词**：发生冲突的不同关键字
- **散列表**(也称哈希表)：一种**根据关键字**直接进行访问的数据结构，建立了**关键字**到**存储地址**的直接映射
#### 构造
1. **定义域**必须包含**全部关键字**，**值域**的范围取决于**散列表**的大小
2. 散列函数计算出的地址应尽可能**均匀地分布**在整个地址空间，以有效减少冲突
3. 散列**函数应尽量简单**，能在较**短时间**内计算出任意关键字对应的散列地址
###### 常用散列函数
| 散列函数      | 公式/方法                                 | 适用情况                     | 优点             | 缺点                  |
| --------- | ------------------------------------- | ------------------------ | -------------- | ------------------- |
| **直接定址法** | $H(key)=key$ 或 $H(key)=a\times key+b$ | **关键字连续**、范围较小           | 计算最快，几乎无冲突     | 空间利用率低，关键字离散时浪费大量空间 |
| **除留余数法** | $H(key)=key\bmod p$（**p一般取≤表长的最大质数**） | **最常用，适用于一般情况**          | 简单、分布较均匀、实现方便  | 会产生冲突，需要配合冲突处理方法    |
| **数字分析法** | 选取关键字中**分布最均匀的若干位**组成地址               | **已知关键字分布规律**（如电话号码、身份证） | 冲突较少，散列效果好     | 必须预先了解关键字分布，不具通用性   |
| **平方取中法** | 对关键字**平方**，再取**中间几位**作为地址             | **关键字位数较少或分布不均**         | 中间位随机性较好，能改善分布 | 计算量稍大，实际应用较少        |
| **折叠法**   | 将关键字**分组后相加**（可再取模）                   | **关键字位数较长**              | 实现简单，适合长关键字    | 分布不一定均匀，冲突可能较多      |
#### 处理冲突
> 任何散列函数都无法绝对避免冲突
###### 1. 开放定址法
> 发生冲突时，不使用链表，而是**继续在散列表中寻找下一个空闲位置** 
$$
H_i=(H(key)+d_i)\bmod m  
$$
- $H(key)$：初始散列地址
- $d_i$：探测序列
- $m$：散列表长度

| 方法        | 探测序列 $d_i$    | 特点                | 操作                                                                          |
| --------- | ------------- | ----------------- | --------------------------------------------------------------------------- |
| **线性探测法** | 0，1，2，3，…     | 最常考，会产生**一次聚集**   | 冲突发生时，顺序查看表中下一个单元；<br>若探测到表尾地址 $m-1$，则下一个 探测地址回绕至表首地址 0；<br>如此循环，直到找到一个空闲单元 |
| **平方探测法** | 0，±1²，±2²，…   | 聚集较轻，但不能保证探测到所有位置 |                                                                             |
| **双散列法**  | 使用第二个散列函数计算步长 | 冲突少，效率高，实现较复杂     |                                                                             |
- 聚集：原本映射到地址 $i$ 的同义词被存 入$i+1$，而本应存入$i+1$的元素则被迫占用$i+2$，以此类推。这会导致大量元素在相邻地址上堆积，显著降低查找效率。
**优点：**
- 不需要额外链表，节省空间
- 缓存局部性好，访问速度快
**缺点：**
- 装填因子高时查找效率下降
- 删除元素较麻烦（通常设置"删除标记"）
**删除操作**：
1. 对被删元素所在位置设置一个删除标记，实现逻辑删除
2. 副作用：经过多次删除后，散列表看似已满，但实际上有许多位置未被利用
###### 2. 拉链法
> 每个散列地址对应**一个链表**，发生冲突时，将元素插入该链表
```text
0 → 26 → 39
1
2 → 15
3
4 → 17 → 30 → 43
```
**优点：**
- 删除方便
- 不易因装填因子增大而急剧降低性能
- 可以存放超过表长的元素
**缺点：**
- 需要额外的链表存储空间
- 指针较多，缓存命中率较低
###### 对比
| 比较项    | 开放定址法      | 拉链法       |
| ------ | ---------- | --------- |
| 冲突处理   | 找空位置       | 建链表       |
| 存储结构   | 全部在散列表内    | 数组 + 链表   |
| 删除     | 较麻烦（需删除标记） | 很方便       |
| 空间利用   | 不需额外指针     | 需要链表空间    |
| 装填因子 α | **必须 α<1** | **可 α>1** |
| 查找效率   | α大时下降明显    | 受链长影响     |
### 性能分析
#### 平均查找长度
###### 成功查找
$$ASL_{成功}=\frac{\sum 每个元素查找次数}{元素个数}$$
> 每个元素查找时比较次数的平均值
###### 失败查找
$$ASL_{失败}=\frac{\sum 每个失败位置比较次数}{散列地址数}$$
> 从每个散列地址开始查找，直到遇到**空位置为止**的平均比较次数
#### 装填因子 α
$$\alpha=\frac{n}{m}$$

- $n$：已存元素个数
- $m$：散列表长度
例如：
```
表长=13
元素=8
```
则
```
α=8/13
```
**作用：**
装填因子**越大**：
- 冲突越**多**
- 查找越**慢**
装填因子**越小**：
- 冲突越**少**
- 空间**浪费越大**
因此：
> **空间利用率与查找效率之间需要折中**
