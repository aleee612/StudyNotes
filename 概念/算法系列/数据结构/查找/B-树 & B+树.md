### B-树（B树）
> m阶B树是一种自平衡的m路查找树，其所有叶结点都位于同一层次
#### 条件
1. 每个结点至多有 $m$ 棵子树，至多包含 $m-1$ 个关键字
2. 若**根结点**不是叶结点，则**至少有 2 棵子树**，即至少包含1个关键字
3. 除根结点外，所有**非叶结点至少有 $m/2$ 棵子树**，即至少**包含$m/2-1$ 个关键字（上取整）** 
4. 每个非叶结点的结构如下
	![[Pasted image 20260717164237.png]]
	其中，$K,(i=1,2,⋯,n)$ 为关键字，
	且满足 $K_1<K_2<⋯<K_n$，
	指针 $P_i(i=0,1,⋯,n)$ 为指向子树根结点的指针；
	指针 $P_{i-1}$ 所指子树中所有关键字均小于$K_i$ 
	指针 $P_i$ 所指子树中所有关键字均大于 $K_i$ 
	%% 更准确地说，介于 $K_i$ 和 $K_{i+1}$ 之间 %%
	$n$ 为该结点中关键字的个数
5. 所有叶结点都出现在同一层次上，且不实际存储数据 %% 对应指针为空，可视为查找失败的外部结点，作用类似于折半查找判定树中的失败结点 %%
#### 特点
![[Pasted image 20260718101933.png]]
1. 任意结点的**子树个数**等于其**关键字**个数**加1** 
2.   若B树为空，则**无结点**
	若非空，则根结点至少包含1个关键字，因此**至少有2棵子树**
3. 除根结点外，所有非叶结点至少有$m/27=5/27=3$ 棵子树（上取整）
	至少包含$m/27-1=2$个关键字
	至多有5棵子树(至多包含m-1=4个关键字
4. 结点中的关键字从左到右**严格递增**
	每个关键字两侧的指针指向其对应的子树：
	**左**侧指针所指子树中的所有关键字均**小于**该关键字，
	**右**侧指针所指子树中的所有关键字均**大于**该关键字
5. 所有叶结点（外部结点）均位于第4层，代表查找失败的位置
#### 高度计算
- 最小高度：
$${h_{\min}=\left\lceil\log_m(n+1)\right\rceil}$$
- 最大高度：
$${ h_{\max} = \left\lfloor \log_{\lceil m/2\rceil} \frac{n+1}{2} \right\rfloor+1 }$$

### B+树
> B+树是在B树基础上改进得到的一种多路平衡查找树，广泛应用于数据库和文件系统索引
![[Pasted image 20260718104125.png]]
#### 条件
1. m阶B+树中，每个分支结点至多有m棵子树（至多包含m个关键字）
2. 若根结点不是叶结点，则至少有2棵子树
3. 除根结点外，所有非叶结点至少有$⌈m/2⌉$棵子树
4. 非叶结点仅用于索引，不保存对应记录；所有**记录**均存放在**叶结点中**
5. 所有叶结点位于**同一层**，并按关键字大小顺序通过指针连接形成有序链表
#### 与B树的差异
| B树             | B+树                    |
| -------------- | ---------------------- |
| 所有结点均可存储记录     | **仅叶结点**存储记录           |
| 非叶结点保存关键字和对应记录 | 非叶结点仅保存关键字作为索引         |
| 关键字仅出现一次       | 非叶结点中的关键字会在叶结点**再次出现** |
| 查找成功可能在任意层结束   | 查找**一定到叶结点结束**         |
| 叶结点之间通常无顺序链接   | 叶结点按关键字大小**链接成链表**     |
| 范围查询效率较低       | 范围查询效率**高**            |
#### 特点
1. 非叶结点只起导航作用，**不存储实际记录**，因此一个结点能容纳更多关键字，树更矮
2. 所有关键字最终都出现在叶结点中，叶结点保存全部记录
3. 所有叶结点通过链表连接，便于顺序访问和范围查询
4. **单点**查找性能与B树**相近**，但**范围查找**明显**优于**B树
5. 数据库（如 MySQL InnoDB）的聚簇索引通常采用B+树实现
#### 查找特点
- 查找任意关键字都必须到达叶结点
- 非叶结点仅用于确定下一步搜索方向
#### 插入与删除
- 插入、删除过程与B树基本一致
- 当结点关键字过多时发生分裂
- 当关键字过少时发生借位或合并
- 分裂、合并可能向上传播，甚至导致树高发生变化
