### 核心概念

| 考点 | 必须记住 |
| --- | --- |
| 虚拟内存 | 在内存和外存之间调入、调出页面，使进程看到的逻辑地址空间可以大于物理内存 |
| 理论基础 | 局部性原理：程序在一段时间内集中访问少量代码和数据 |
| 实现条件 | 离散分配；页表等地址转换机构；缺页中断机构；外存具有页面副本或交换区 |
| 三个特征 | 多次性：作业分多次调入；对换性：运行时允许换入、换出；虚拟性：逻辑容量不受物理内存容量直接限制 |
| 请求分页 | 页面首次被访问且不在内存时才调入；区别于运行前装入全部页面的基本分页 |
| 驻留集 | 某进程当前实际驻留在物理内存中的页面集合；过小会频繁缺页，过大会挤压其他进程 |

> [!warning] 易错
> 虚拟内存扩大的是逻辑地址空间，不会扩大物理内存；其最大容量还受计算机地址结构和外存容量限制。

### 请求分页与缺页中断

| 页表项字段 | 作用 | 题目中的判断 |
| --- | --- | --- |
| 页框号 | 指出页面所在的物理块 | 页面在内存时用于地址转换 |
| 存在位/有效位 | 表示页面当前是否在内存 | 为 0 且访问合法时触发[[缺页中断]] |
| 访问位 | 表示页面近期是否被访问 | CLOCK 等置换算法使用 |
| 修改位/脏位 | 表示调入后是否被修改 | 换出脏页前必须写回外存 |
| 保护位 | 记录读、写、执行权限 | 权限不符是保护异常，不是缺页 |
| 外存地址 | 记录页面在外存中的位置 | 缺页时据此把页面调入 |

缺页处理顺序：

1. MMU 查页表，发现页面不在内存，陷入内核。
2. 检查访问是否合法；非法访问直接终止或报告异常。
3. 有空闲页框则直接使用；否则选择牺牲页。
4. 牺牲页若为脏页，先写回外存。
5. 从外存读入所需页面；进程在 I/O 期间阻塞，处理机调度其他进程。
6. 更新页表和失效的 TLB 表项，重新执行引发缺页的指令。

> [!warning] 高频判断
> 缺页中断属于内部异常中的故障（Fault），一条指令执行期间可能发生多次缺页；处理完成后应重新执行该指令。TLB 未命中只需要查页表，不等于缺页。

### 页面置换算法

| 算法 | 选择谁换出 | 高频结论 | 最易错 |
| --- | --- | --- | --- |
| OPT | 未来最长时间不再访问的页面 | 缺页次数最少，用作理论最优结果 | 需要预知未来，实际无法实现 |
| FIFO | 最早进入内存的页面 | 实现简单 | 可能出现 Belady 异常 |
| LRU | 过去最长时间没有访问的页面 | 利用最近的访问历史，属于堆栈算法 | 不能用“进入内存最早”判断；不会出现 Belady 异常 |
| CLOCK | 从指针位置扫描；访问位为 0 时换出，为 1 时清零并跳过 | 用访问位近似 LRU | 指针从上次停止位置继续，不是每次从头扫描 |
| 改进型 CLOCK | 综合访问位 A 和修改位 M | 优先换出（0，0），其次（0，1）；访问过的页面获得第二次机会 | M＝1 的页面换出前要写回，因此同等访问情况下更晚换出 |

> [!tip] 置换题步骤
> 逐项扫描页面访问串并画出页框；首次装入也算缺页，只有页框已满后才发生置换。题目问缺页率时：缺页率＝缺页次数÷页面访问总次数。

### 页框分配与置换范围

| 策略        | 页框数    | 牺牲页范围             | 特点                   |
| --------- | ------ | ----------------- | -------------------- |
| 固定分配＋局部置换 | 运行期间固定 | 只能从本进程驻留集中选择      | 进程相互影响小，但不能动态适应需求    |
| 可变分配＋局部置换 | 可增减    | 置换时先从本进程选择        | 根据缺页情况调整驻留集，能控制进程间干扰 |
| 可变分配＋全局置换 | 可增减    | 可从系统中的可用页框或其他进程选择 | 利用率高，但进程会相互影响，容易扩大抖动 |

页框分配量还可能采用平均分配、按进程大小比例分配或按优先级分配；每个进程至少要获得能够完成一条指令所需的最少页框数。

> [!warning] 易错
> “固定分配＋全局置换”自相矛盾：如果能夺取其他进程的页框，各进程的页框数就不再固定。

### 抖动、工作集与缺页率

| 概念 | 判断与处理 |
| --- | --- |
| 抖动/颠簸 | 进程页框不足，刚换出的页面很快又被访问，系统把大量时间用于换页而非执行指令 |
| 直接原因 | 分配给进程的页框不能覆盖当前局部；并发进程过多会加剧页框竞争 |
| 工作集 | 最近一个窗口 Δ 内访问过的页面集合，用来估计当前局部需要的页框 |
| 工作集策略 | 各进程工作集需求总量超过可用页框时，应暂停部分进程、降低多道程序度 |
| 缺页率 PFF | 缺页率过高则增加页框；过低则回收部分页框；无空闲页框时可暂停进程 |

> [!warning] 易错
> CPU 利用率因频繁缺页而下降时，继续增加并发进程通常会让抖动更严重，正确方向是降低多道程序度。

### 页面大小与性能计算

| 页面较小 | 页面较大 |
| --- | --- |
| 页内碎片较小 | 页内碎片较大 |
| 页表项更多、页表占用更大 | 页表项更少、页表占用更小 |
| 同样数量的 TLB 表项覆盖范围较小 | TLB 覆盖范围较大 |
| 单次 I/O 传输量较小 | 单次 I/O 传输量较大，但可能调入更多暂时无用的数据 |

缺页有效访问时间的统一写法：

$$EAT=(1-p)\times T_{正常访问}+p\times T_{缺页处理}$$

其中 $p$ 为缺页率；缺页处理包含陷入、必要时写回牺牲页、读入所需页、更新页表并重新执行指令。磁盘 I/O 远慢于内存访问，因此很小的缺页率也会显著降低性能。

> [!warning] 易错
> 页面变大并不保证缺页次数一定下降：它既可能利用空间局部性，也可能一次调入大量无用数据。此类结论必须结合访问串或题设判断。
