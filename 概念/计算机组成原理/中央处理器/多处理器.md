| 考点        | 结论                |
| --------- | ----------------- |
| SMP       | 多 CPU 共享主存、统一地址空间 |
| UMA       | 所有 CPU 访问内存速度一致   |
| NUMA      | 本地快，远程慢           |
| Cache 一致性 | 多 Cache 保存同一数据导致  |
| MESI      | M、E、S、I 四状态       |
| MESI 写策略  | 写失效（Invalidate）   |
| CPU 少     | 总线监听              |
| CPU 多     | 目录协议              |
# 弗林分类法
> 弗林分类法根据**指令流**和**数据流**的数量，将计算机体系结构划分为四类

|   数据流\指令流    | 单指令流（SI） | 多指令流（MI） |
| :----------: | :------: | :------: |
| **单数据流（SD）** |   SISD   |   MISD   |
| **多数据流（MD）** |   SIMD   |   MIMD   |
其中：
- **指令流**：程序执行的一系列指令，即**计算机要做什么**
- **数据流**：程序执行过程中处理的数据，即**计算机处理什么**
> 因此，弗林分类法实际上就是根据**指令是否相同**、**数据是否相同**来划分计算机体系结构

---
# SISD
SISD 即**单指令流、单数据流**，也是最传统的计算机体系结构
###### 特点：
- 只有一个处理单元（PU）
- 每次执行一条指令
- 每次处理一份数据
- 所有操作按顺序串行完成
###### 典型代表：
- 传统单核CPU
- 普通串行计算机
**一句话记忆：**
> 一个处理器，执行一条指令，处理一份数据
# SIMD
> SIMD 即**单指令流、多数据流**
> 它通过**一条指令控制多个处理单元同时工作**，每个处理单元执行完全相同的操作，但处理的数据不同，因此能够实现**数据级并行**
###### 特点：
- 一条指令控制多个处理单元
- 所有处理单元执行相同指令
- 每个处理单元处理不同数据
- 特别适合大量重复计算
> [!note] 例：矩阵加法
假设需要完成一个 **N × N** 矩阵相加
普通单处理器需要执行N² 次加法
若采用 SIMD，并拥有 **N 个处理单元**
每次可以同时计算一整行，共只需要N 次
因此 SIMD 可以显著提高矩阵运算、图像处理等数据密集型任务的效率

典型应用：
- 向量计算
- 矩阵运算
- 图像处理
- 视频处理
- 科学计算
**一句话记忆：**
> 一条命令，大家一起干

## SIMD 与 SIMT
SIMD属于**硬件级的数据并行**
CPU 通过增加多个处理单元，使多个处理单元在同一时刻执行**完全相同**的指令，只是处理的数据不同

SIMT则是 GPU 采用的一种线程并行模型
它也是让多个线程同时执行同一条指令，但允许线程在一定程度上发生**分支）**，因此不同线程在某些时刻可以执行不同的路径，比 SIMD 更灵活

| SIMD | SIMT |
|------|------|
| 面向数据 | 面向线程 |
| 多个处理单元 | 多个线程 |
| 必须执行相同指令 | 允许线程分支 |
| 常见于CPU向量计算 | 常见于GPU |
# MISD
> MISD 即**多指令流、单数据流**
- 多个处理单元同时对**同一份数据**执行**不同的指令**
- 由于实现困难，而且适用场景极少，因此现实中几乎看不到真正的 MISD 系统
- 少数**容错系统**会采用这种思想：多个处理器分别对同一份数据采用不同算法进行计算，再比较结果是否一致，以提高可靠性
**一句话记忆：**
> 同一份数据，不同算法
# MIMD
> MIMD 即**多指令流、多数据流**
- 多个处理单元能够独立执行不同程序，并处理不同的数据，因此具有最高的灵活性
- 现代绝大多数并行计算机都属于 MIMD，例如：
	- 多核CPU
	- 多处理器服务器
	- 高性能计算机
SIMD 与 MIMD 的最大区别在于：
- **SIMD：所有处理单元执行相同指令**
- **MIMD：每个处理单元都可以执行不同指令**

| 类型 | 指令流 | 数据流 | 特点 | 典型代表 |
|------|------|------|------|------|
| SISD | 单 | 单 | 串行执行 | 单核CPU |
| SIMD | 单 | 多 | 同一指令处理多份数据 | 向量机、图像处理 |
| MISD | 多 | 单 | 同一数据执行不同指令 | 容错系统 |
| MIMD | 多 | 多 | 不同指令处理不同数据 | 多核CPU |
**口诀：**
```
SISD：一个人干一件事
SIMD：大家执行同一命令
MISD：同一数据，不同算法
MIMD：大家各干各的
```

# 多核处理器
现代 CPU 基本都采用**多核**设计，本质上属于 **MIMD** 架构

与单核处理器相比，多核处理器将多个处理核心集成到同一块 CPU 芯片上，每个核心都能够独立执行程序，从而实现真正的并行计算

相比增加 CPU 主频，多核设计具有**功耗更低、扩展能力更强**等优点，因此已经成为现代处理器的发展方向
# 物理核心、逻辑核心与超线程

| 项目     | 物理核心                   | 逻辑核心                  | 超线程                                     |
| ------ | ---------------------- | --------------------- | --------------------------------------- |
| 本质     | CPU 中真实存在的处理单元         | 操作系统识别的虚拟处理单元         | 在一个物理核心上模拟多个逻辑核心的技术                     |
| 是否真实硬件 | ✔ 是                    | ✘ 否                   | ——                                      |
| 拥有资源   | 独立寄存器、运算单元、L1/L2 Cache | 共享所属物理核心的大部分硬件资源      | 两个逻辑核心共享 Cache、运算单元、执行单元等资源，但拥有各自的寄存器状态 |
| 数量关系   | 一个 CPU 可有多个物理核心        | 一个物理核心可对应多个逻辑核心       | 使一个物理核心对应多个逻辑核心                         |
| 性能     | 可独立执行程序                | 性能受物理核心资源限制           | 性能通常提升 **20%～30%**，不会翻倍                 |
| 例子     | 四核 CPU 有 4 个物理核心       | 四核八线程：操作系统识别为 8 个逻辑核心 | 四核八线程即采用超线程技术                           |
> **物理核心是真房子，逻辑核心是房间，超线程就是把一个房子隔成多个房间**

# 共享内存多处理机

共享内存多处理机是一种典型的并行计算机体系结构，其特点是**多个处理器共享同一块物理内存**，处理器之间通过读写共享内存实现通信和数据交换
**系统组成：**
- 多个处理器
- 系统互连网络（总线、交叉开关、多级网络等）
- 共享主存
- I/O设备
**主要特点：**

| 特点 | 说明 |
|------|------|
| 共享内存 | 所有处理器共享同一物理内存，通过共享内存完成通信和同步 |
| 处理器互连 | 处理器通过总线、交叉开关、多级网络等连接共享主存，互连网络性能直接影响系统性能 |
**一句话记忆：**
> 多个处理器，共享一块主存，通过互连网络进行通信

# SMP
SMP 是最常见的共享内存多处理机结构，多个 CPU **共享主存、共享统一地址空间**，所有 CPU 地位平等

| 特点 | 说明 |
|------|------|
| 主存 | 多个 CPU 共享 |
| 地址空间 | 统一地址空间 |
| CPU 地位 | 平等，无主从关系 |
| Cache | 每个 CPU 通常拥有自己的 L1/L2 Cache（部分共享 L3） |
| 问题 | 存在 Cache 一致性问题 |

**一句话记忆：**
> 多 CPU 共享主存，CPU 平等，需要解决 Cache 一致性

# UMA 与 NUMA

| 对比 | UMA | NUMA |
|------|------|------|
| 全称 | Uniform Memory Access | Non-Uniform Memory Access |
| 主存 | 共享 | 分布式共享 |
| 访问延迟 | 相同 | 不同 |
| 本地内存 | 无区别 | 本地最快 |
| 远程内存 | 无区别 | 较慢 |
| 扩展性 | 较差 | 较好 |
| 优点 | 编程简单 | 扩展能力强 |
| 缺点 | 总线易成为瓶颈 | 编程较复杂 |

**口诀：**
> UMA：人人一样快；NUMA：本地快，远程慢
# Cache 一致性
多个 CPU 拥有各自 Cache，同一数据可能存在多个副本。当某个 CPU 修改数据后，其他 CPU 若仍读取旧副本，就会产生 **Cache 一致性问题**
**常见协议：**

| 协议 | 考频 |
|------|------|
| MSI | 了解 |
| MESI | ★★★★★ |

**一句话记忆：**
> 多 Cache 保存同一数据，需要保证数据一致
# MESI 协议

| 状态 | 含义 | 特点 |
|------|------|------|
| **M** | Modified（已修改） | 主存数据已过期，仅当前 Cache 拥有，替换时需写回主存 |
| **E** | Exclusive（独占） | 仅当前 Cache 拥有，与主存一致，可直接修改为 M |
| **S** | Shared（共享） | 多个 Cache 共享，与主存一致；写入时其他 Cache 失效 |
| **I** | Invalid（失效） | Cache 副本失效，需要重新读取 |

**口诀：**

```
M：改
E：独
S：共
I：废
```

# 写失效与写更新

| 策略  | 工作方式                 | 优点     | 缺点        |
| --- | -------------------- | ------ | --------- |
| 写失效 | 修改数据后，使其他 Cache 副本失效 | 通信量小   | 下次访问需重新读取 |
| 写更新 | 修改数据后，同时更新其他 Cache   | 数据始终最新 | 通信量大      |
> **MESI 采用：写失效**
# Cache 一致性的实现

| 实现方式 | 原理              | 适用场景           |
| ---- | --------------- | -------------- |
| 总线监听 | Cache 监听总线上的写操作 | CPU 数量较少       |
| 目录协议 | 目录记录数据副本位置并统一管理 | CPU 数量较多（NUMA） |
# 多处理器同步
多个 CPU **同时访问**共享变量时，需要同步机制避免数据竞争

| 同步方式    | 作用       |
| ------- | -------- |
| 锁（Lock） | 保证互斥访问   |
| 信号量     | 控制资源访问   |
| 原子操作    | 保证操作不可分割 |

> **作用：保证同一时刻只有一个 CPU 修改共享数据**```
