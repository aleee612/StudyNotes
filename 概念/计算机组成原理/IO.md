### I/O 系统
#### I/O 接口
**功能：**
- 数据缓冲（速度匹配）
- 数据格式转换
- 控制和定时
- 状态/错误检测
> I/O接口≈设备控制器（408一般不区分）
#### I/O 端口
> CPU 可直接访问的接口寄存器

| 端口   | 作用         |
| ---- | ---------- |
| 数据端口 | 数据传输       |
| 状态端口 | 保存设备状态（只读） |
| 控制端口 | 接收控制命令（只写） |
#### I/O 编址
| MMIO（统一编址） | PMIO（独立编址） |
| ---------- | ---------- |
| 与内存共用地址空间  | 独立I/O地址空间  |
| 普通访存指令     | IN/OUT指令   |
| 占用内存地址     | 不占用内存地址    |
- MMIO：设备寄存器映射到内存地址空间，使用普通内存读写指令访问
- PMIO：设备拥有独立的 I/O 地址空间，只能使用 `IN/OUT` 等专用 I/O 指令访问
#### 四种 I/O 方式
| 方式   | CPU等待 | CPU搬运数据 | 数据路径        |
| ---- | ----- | ------- | ----------- |
| 程序查询 | √     | √       | 设备→CPU→主存   |
| 程序中断 | ×     | √       | 设备→CPU→主存   |
| DMA  | ×     | ×       | 设备→主存       |
| 通道   | ×     | ×       | 设备→主存（通道控制） |
> CPU参与程度：程序查询 ＞ 程序中断 ＞ DMA ＞ 通道

### DMA
> DMA（直接存储器访问）：**由 DMA 控制器完成外设与主存之间的数据传输，CPU 不参与数据搬运**

CPU：
- 初始化 DMA（设置地址、长度、方向等）
- 传输结束后处理中断

DMA：
- 申请总线控制权
- 外设 ↔ 主存直接传输数据
- 完成后向 CPU 发送中断

###### DMA 工作过程
| 阶段         | 执行者       | 主要内容                                                       |
| ---------- | --------- | ---------------------------------------------------------- |
| **预处理**    | CPU       | 初始化 DMA（设置外设地址、主存地址、传输长度、方向、工作方式），启动 DMA 和外设               |
| **DMA 请求** | 外设 → DMA  | 外设准备就绪，向 DMA 发出请求；DMA 向 CPU/总线仲裁器申请总线控制权                   |
| **获得总线**   | CPU → DMA | CPU 完成当前总线周期后让出总线，DMA 获得总线控制权                              |
| **数据传输**   | DMA       | 在 **I/O 接口 ↔ 主存** 间直接传输数据，自动修改地址（MAR）、更新计数（DC），CPU 不参与数据搬运 |
| **释放总线**   | DMA       | 数据传输结束，释放总线控制权，交还 CPU                                      |
| **后处理**    | CPU       | DMA 发出完成中断，CPU 响应中断，检查传输结果并完成收尾工作                          |

DMA 控制器：
- MAR：内存地址寄存器
- DR：数据寄存器
- DC：数据计数器
- CR：控制/状态寄存器
###### DMA 使用总线方式
| 方式             | 特点                                  | CPU 是否可访存    |
| -------------- | ----------------------------------- | ------------ |
| **总线独占**       | DMA 独占总线，传输完成后才归还总线                 | 不可           |
| **周期挪用（循环窃取）** | DMA 每次只占用一个（或少数几个）总线周期，与 CPU 交替使用总线 | 可以（DMA 未占用时） |
| **分时多路复用**     | CPU 与 DMA 按预定时隙轮流使用总线               | 可以（按时隙）      |
> **DMA 与 CPU 同时申请总线时，DMA 优先级高于 CPU**

> **特点：** CPU 仅参与首尾，适用于高速、大批量数据传输

### 通道
> **通道：具有执行 I/O 指令能力的处理机，可独立管理 I/O 操作**

CPU：
- 只启动通道程序
- 接收完成中断

通道：
- 执行通道程序
- 控制设备
- 管理多个设备的数据传输

DMA 与通道：
- DMA：CPU **每次**都要初始化 DMA
- 通道：CPU **只启动一次**通道程序，其余由通道独立完成
> **特点：** 比 DMA 自动化程度更高，适用于大型机、高性能计算机

| 比较项        | DMA               | 通道             |
| ---------- | ----------------- | -------------- |
| 控制者        | DMA 控制器           | 通道（I/O 处理机）    |
| 是否具有执行指令能力 | 没有                | 有，可执行通道程序      |
| CPU 参与程度   | 每次 DMA 都需 CPU 初始化 | CPU 只需启动一次通道程序 |
| 能否管理多个设备   | 一般较弱              | 可以同时管理多个设备     |
| 应用场景       | 微机、PC、服务器         | 大型机、高性能计算机     |
