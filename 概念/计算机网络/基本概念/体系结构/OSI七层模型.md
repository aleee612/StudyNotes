### 层次对应

| OSI 七层      | 五层模型  | TCP/IP 四层 |
| ----------- | ----- | --------- |
| **应用层、表示层、会话层** | **应用层**   | **应用层**       |
| 传输层         | 传输层   | 传输层       |
| 网络层         | 网络层   | 网际层       |
| 数据链路层       | 数据链路层 | 网络接口层     |
| 物理层         | 物理层   | 网络接口层     |

- OSI：物理、数据链路、网络、传输、会话、表示、应用。
- TCP/IP：网络接口、网际、传输、应用。
- 五层模型：把 TCP/IP 的网络接口层拆成物理层和数据链路层，把 OSI 顶部三层合并为应用层。

### 各层区分

| 层次 | 通信范围 | 处理内容 | 数据单位 | 标识或设备 |
| --- | --- | --- | --- | --- |
| 应用层 | 应用进程之间 | 具体网络服务和应用协议 | 报文 | 域名、URL、应用协议字段 |
| 传输层 | 进程到进程 | 复用与分用；按协议提供可靠或不可靠传输 | TCP 报文段、UDP 用户数据报 | 端口号 |
| 网络层 | 主机到主机 | 逻辑寻址、路由选择、分组转发 | IP 数据报、分组 | IP 地址、路由器 |
| 数据链路层 | 相邻结点 | 组帧、透明传输、差错检测、介质访问控制 | 帧 | MAC 地址、网桥、交换机 |
| 物理层 | 相邻接口 | 传输比特，规定物理接口特性 | 比特 | 中继器、集线器 |

OSI 顶部三层：  

- 会话层：会话管理、对话控制、同步和检查点。
- 表示层：编码转换、压缩、加密和解密。
- 应用层：向应用进程提供网络服务，不等于用户应用程序本身。

### 面向连接与无连接

| 体系 | 网络层或网际层 | 传输层 |
| --- | --- | --- |
| OSI | 同时支持面向连接和无连接服务 | 主要提供面向连接服务 |
| TCP/IP | IP 提供无连接的数据报服务 | TCP 面向连接；UDP 无连接 |

- 面向连接**不等于可靠**；建立逻辑连接只表示通信双方**维护状态**。
- 可靠传输还需要确认、序号、重传、差错检测和排序等机制。
- IP 无连接与 TCP 面向连接不矛盾：TCP 状态保存在端系统，沿途 IP 路由器不维护 TCP 连接。
- 虚电路是网络层的面向连接服务，仍采用分组交换；不等于电路交换，也不天然保证可靠。

### OSI 与 TCP/IP

| 对比 | OSI | TCP/IP |
| --- | --- | --- |
| 层数 | 七层 | 四层 |
| 形成过程 | 先提出参考模型，再设计协议 | 先有协议，再归纳体系结构 |
| 性质 | 通用参考模型，协议独立 | 实际使用的因特网协议体系 |
| 顶部层次 | 应用、表示、会话分开 | 三者功能并入应用层 |
| 底部层次 | 物理层和数据链路层分开 | 合并为网络接口层 |
| 服务安排 | 网络层支持两类服务，传输层主要面向连接 | 网际层无连接，传输层支持 TCP 和 UDP |

- OSI 对服务、接口、协议三者区分明确；TCP/IP 对其划分没有 OSI 严格。
- OSI 是参考模型，不是因特网实际运行的七层协议栈。
- TCP/IP 模型中的“TCP”不表示所有传输层通信都使用 TCP，UDP 同样属于传输层。

### 封装与分用

发送端：应用报文 → TCP 报文段或 UDP 用户数据报 → IP 数据报 → 帧 → 比特。  
接收端按相反方向解封装。

| 交付方向 | 分用依据 |
| --- | --- |
| 数据链路层 → 网络层 | 帧的类型字段 |
| IPv4 → 上层协议 | 协议字段 |
| IPv6 → 后续首部或上层协议 | 下一个首部字段 |
| 传输层 → 应用进程 | 目的端口号 |

- 协议是同层对等实体之间的规则；服务是下层向上层提供的功能；接口位于相邻层之间。
- 除物理层外，对等层之间是逻辑通信，数据实际沿协议栈逐层传递。
- PDU、SDU、PCI 及协议三要素见[[协议、服务与接口]] 
- 完整封装名称见[[报文单位与封装]] 

### 同名功能所在层

| **功能**   | 数据链路层           | 网络层                      | 传输层                   |
| ---- | --------------- | ------------------------ | --------------------- |
| **通信对象** | 相邻结点            | 主机到主机                    | 进程到进程                 |
| **寻址**   | MAC 地址          | IP 地址                    | 端口号                   |
| **流量控制** | 控制相邻发送方与接收方的速率  | —                        | 控制端到端发送方与接收方的速率       |
| **差错检测** | FCS 检测当前链路上的帧   | IPv4 只校验首部；IPv6 基本首部无校验和 | TCP/UDP 校验和覆盖报文并包含伪首部 |
| **可靠传输** | 某些协议可提供，范围是相邻结点 | IP 本身不可靠                 | TCP 可靠，UDP 不可靠        |
| **拥塞控制** | 不是经典链路层流量控制的对象  | 网络设备可参与                  | 经典 TCP 在端系统实施         |

流量控制协调发送方与接收方；拥塞控制处理网络整体负载，两者不能混为一谈。

### 设备处理层次

| 设备       | 最高处理层次 | 转发依据    |
| -------- | ------ | ------- |
| 中继器、集线器  | 物理层    | 比特信号    |
| 网桥、二层交换机 | 数据链路层  | MAC 地址表 |
| 路由器      | 网络层    | IP 转发表  |

- 集线器不识别帧和地址。
- 二层交换机读取帧，不进行普通 IP 路由。
- 路由器拆除旧链路层首尾，根据目的 IP 选择下一跳，再重新封装新的帧。
- 普通主机实现完整协议栈；路由器通常处理五层模型的下三层。
