### IP

> [!summary] 核心定位
> IP 是互联网网络层的核心协议，为主机提供无连接、尽力而为的数据报服务。它解决“分组从哪台主机发往哪台主机、路由器下一步把分组送向哪里”的问题，但不保证分组不丢失、不重复、按序到达或时延固定。

#### IP 提供什么

- **逻辑寻址**：用 IP 地址标识网络接口，使不同链路上的设备能组成统一的互联网；
- **封装**：把 TCP、UDP、ICMP 等上层数据封装成 IP 数据报；
- **转发**：路由器根据目的 IP 地址查询转发表，把数据报送往下一跳；
- **跨异构网络传输**：同一个 IP 数据报可以依次承载在以太网、无线局域网、点到点链路等不同链路层协议之上。
#### IP 不提供什么
IP 的“尽力而为”意味着它本身不承诺：

- 可靠交付；
- 按序交付；
- 不重复；
- 固定时延或固定带宽；
- 端到端拥塞控制和流量控制。

需要可靠性、顺序和拥塞控制时，通常由 [[TCP]] 等更高层协议实现。

#### 转发与路由选择的区别
- **转发**属于数据平面：路由器对到达的每个分组查转发表并选择输出端口，是局部、逐分组的动作；
- **路由选择**属于控制平面：通过静态配置或 RIP、OSPF、BGP 等协议计算路径并生成路由信息，是全局、较慢时间尺度的过程。

路由器匹配的是**目的 IP 地址的网络前缀**，存在多个匹配项时采用[[子网划分与路由聚合#最长前缀匹配|最长前缀匹配]]
#### 地址属于接口

严格来说，IP 地址分配给网络接口，而不是抽象地“分配给整台设备”：

- 普通主机可能只有一个活动接口和一个主要 IP 地址；
- 路由器连接多条链路，每个三层接口通常都有自己的 IP 地址；
- 一台多宿主主机也可以同时拥有多个 IP 地址。
#### IP 地址与 MAC 地址的作用范围

- IP 地址用于端到端的逻辑寻址，普通路由转发过程中源、目的 IP 通常保持不变；NAT 等中间功能是例外；
- MAC 地址只在当前链路中使用，每经过一台路由器都要重新封装链路层帧，因此源、目的 MAC 会逐跳变化；
- ARP 解析的是**本地链路上下一跳 IPv4 地址对应的 MAC 地址**，不是单独解析所谓“主机号”，也不会查询远端主机跨越互联网后的 MAC 地址。
#### 408 高频判断

> [!warning] 易错点
> - IP 是无连接、尽力而为的，不等于完全不做差错检测：IPv4 有首部校验和，但只检查首部。
> - IP 数据报的目的地址是最终目的接口的 IP；把帧交给默认网关时，目的 MAC 是网关 MAC，但目的 IP 仍是最终主机 IP。
> - 路由器根据目的 IP 的网络前缀转发，不根据传输层端口号进行普通 IP 转发。
> - `0.0.0.0` 是未指定 IPv4 地址；默认路由必须写作 `0.0.0.0/0`，两者含义不同。
