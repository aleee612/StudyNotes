### IPv4 数据报

> [!summary] 核心结论
> IPv4 地址长 32 bit
> IPv4 数据报由 20～60 B 的可变长首部和数据组成
> 总长度最大为 65 535 B
> 路由器主要根据目的 IPv4 地址转发，并在每一跳减少 TTL、更新首部校验和

#### 数据报格式
![[Pasted image 20251019202309.png]]

| **字段**       |     长度 | 含义与考点                                        |
| -------- | -----: | -------------------------------------------- |
| **版本**       |  4 bit | IPv4 中取值为 4                                  |
| **首部长度 IHL** |  4 bit | 单位为 4 B；最小值 5，即 20 B；最大值 15，即 60 B           |
| **区分服务**     |  8 bit | 现代解释通常为 DSCP 6 bit 加 ECN 2 bit，用于服务质量与显式拥塞通知 |
| **总长度**      | 16 bit | 整个数据报的长度，即首部加数据；最大为 65 535 B                 |
| **标识**       | 16 bit | 同一原始数据报产生的各分片使用相同标识，供目的主机重组                  |
| **标志**       |  3 bit | 保留位、DF、MF；DF=1 禁止分片，MF=1 表示后面还有分片            |
| **片偏移**      | 13 bit | 表示本片数据在原数据部分中的位置，单位为 8 B                     |
| **生存时间 TTL** |  8 bit | 每经过一台路由器至少减 1；变为 0 时丢弃并通常返回 ICMP 超时报文        |
| **协议**       |  8 bit | 指明数据交给哪个上层协议，例如 ICMP=1、TCP=6、UDP=17、OSPF=89  |
| **首部校验和**    | 16 bit | 只检查 IPv4 首部；TTL 每跳变化，因此路由器需要更新校验和            |
| **源地址**      | 32 bit | 源接口的 IPv4 地址；普通转发时不变，NAT 可能修改                |
| **目的地址**     | 32 bit | 最终目的接口的 IPv4 地址；普通转发时不变，NAT 可能修改             |
| **选项与填充**    | 0～40 B | 可选；填充后使首部长度为 4 B 的整数倍                        |
| **数据**       |     可变 | TCP、UDP、ICMP 等协议的数据                          |

#### 首部长度与数据长度计算
若 IHL 字段值为 $k$，则：
$$
IPv4\ 首部长度 = 4k\ \mathrm{B}
$$

$$
数据长度 = 总长度 - 首部长度
$$

例如 IHL=5、总长度=1500 B，则首部为 20 B，数据为 1480 B
#### 分用依据
接收方去掉 IPv4 首部后，根据“协议”字段把数据交给相应模块：

- 1：ICMP；
- 2：IGMP；
- 6：TCP；
- 17：UDP；
- 89：OSPF

这与数据链路层根据帧的类型字段分用、运输层根据端口号分用不同
#### 每经过一台普通路由器
路由器通常执行：
1. 去掉入站链路的帧首部和尾部；
2. 检查 IPv4 首部；
3. 将 TTL 至少减 1，若变为 0 则丢弃；
4. 因 TTL 改变而更新 IPv4 首部校验和；
5. 根据目的地址执行最长前缀匹配；
6. 必要时处理 [[MTU与IP分片|MTU 和分片]]；
7. 用出站链路的新源、目的 MAC 地址重新封装成帧

普通路由转发中，源、目的 IPv4 地址不变；NAT、隧道等功能是例外

#### 常见特殊地址和地址块

| 地址或前缀 | 含义 |
| --- | --- |
| `0.0.0.0` | 未指定地址，常作为主机尚未获得地址时的源地址；不是默认路由的完整写法 |
| `0.0.0.0/0` | 默认路由，前缀长度为 0，可匹配任意 IPv4 目的地址 |
| `127.0.0.0/8` | 回环地址块，最常用的是 `127.0.0.1`；报文不离开本机 |
| `255.255.255.255` | 受限广播地址，只在本地网络内使用，路由器不转发 |
| 某子网主机位全 1 | 该子网的定向广播地址；是否允许路由器转发取决于配置，通常被禁用 |
| `169.254.0.0/16` | IPv4 链路本地地址，只在本地链路有效 |
| `10.0.0.0/8` | 私有地址块 |
| `172.16.0.0/12` | 私有地址块，即 `172.16.0.0`～`172.31.255.255` |
| `192.168.0.0/16` | 私有地址块 |
| `224.0.0.0/4` | IPv4 多播地址块 |
| `240.0.0.0/4` | 保留地址空间；`255.255.255.255` 另有受限广播含义 |

网络地址、广播地址和可用主机范围的计算统一见 [[子网划分与路由聚合]]；私有地址的转换见 [[NAT]]

#### IPv4 地址与接口
- IPv4 地址长 32 bit，通常使用点分十进制表示；
- 地址由网络前缀和主机部分组成，前缀长度用 `/p` 表示；
- 地址分配给接口，路由器的不同三层接口通常拥有不同地址；
- 同网段通信时，ARP 查询目的主机接口的 MAC；跨网段通信时，ARP 查询默认网关接口的 MAC。

#### 首部校验和
IPv4 首部校验和采用 16 bit 反码算术：

1. 计算时先把校验和字段置 0；
2. 将首部按 16 bit 分组进行反码加法；
3. 对结果按位取反得到校验和；
4. 接收方把包含校验和的所有 16 bit 字相加，结果应为全 1。

它只保护首部，不保护数据部分。TCP 和 UDP 的校验和负责运输层报文段，并结合 IP 伪首部参与计算。

#### 408 高频易错点

> [!warning] 易错点
> - IHL 的单位是 4 B，片偏移的单位是 8 B，二者不能混淆。
> - 总长度包含 IPv4 首部，片偏移只按原数据部分的位置计算。
> - MF=0 既可能表示“最后一片”，也可能表示“从未分片的数据报”。
> - DF=1 且数据报超过下一链路 MTU 时，路由器不能分片，应丢弃并返回 ICMP 差错信息。
> - `0.0.0.0` 不等于 `0.0.0.0/0`。
> - ARP 映射的是下一跳 IPv4 地址与 MAC 地址，不是“查询主机号”。
