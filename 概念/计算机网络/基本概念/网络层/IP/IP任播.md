### IP 任播

> [!summary] 核心结论
> 任播让多个节点使用或对外宣告同一个 IP 地址，路由系统把每个请求送往按当前路由度量最合适的一个节点。“最近”是路由意义上的最优，不一定是地理距离最近。

#### 工作原理

1. 位于不同位置的多个服务节点使用同一个服务地址或宣告同一个地址前缀；
2. 路由协议学习到达这些节点的多条路径；
3. 路由器根据协议规则和度量选择其中一条最佳路径；
4. 用户分组被送到该路径对应的一个服务节点。

任播不要求发送主机知道背后有多少节点，选择主要由路由系统完成。

#### 地址形式

- IPv6 在体系结构中明确规定任播，同一个单播地址可以分配给多个接口；任播地址没有独立的格式或专用前缀；
- IPv4 没有单独的任播地址类别，但工程上可以让多个节点通过 BGP 等方式宣告同一前缀，实现任播效果；
- 因此不能通过观察一个普通 IP 地址的二进制格式，就断定它一定是单播还是任播。

#### 常见用途

- DNS 根服务器和公共 DNS 服务；
- CDN、边缘代理和抗 DDoS 清洗节点；
- 分布式网关或其他要求就近接入、高可用的服务。

任播常与 [[BGP 边界网关协议|BGP]] 结合：不同站点向外宣告同一服务前缀，BGP 根据策略和路径属性决定可达路径。

#### 与单播、多播的区别

| 类型 | 地址对应关系 | 接收结果 |
| --- | --- | --- |
| 单播 | 一个地址通常标识一个接口 | 交付给唯一目的接口 |
| 多播 | 一个地址标识一个接收组 | 交付给组内多个成员 |
| 任播 | 多个接口共享同一地址 | 交付给路由意义上最合适的一个成员 |

#### 局限

- 路由变化可能让同一用户后续分组改道到不同节点；
- 对长连接服务，需要保持路由稳定或在应用层设计状态同步与容错；
- “距离最近”不保证时延最低，实际结果取决于路由策略、度量和网络状态；
- 任播提供的是路由选择能力，不自动完成负载均衡、健康检查和应用状态复制。

#### 408 高频判断

> [!warning] 易错点
> - 任播是一对“多个候选中的一个”，多播才是一对多。
> - 任播选择的“最近节点”由路由协议决定，不一定是物理位置最近。
> - IPv6 任播地址取自单播地址空间，没有专用任播前缀。
> - DNS 的“主机别名”是域名系统中的名称映射，与 IP 任播不是同一个概念。
