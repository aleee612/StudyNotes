### MTU 与 IP 分片
> [!summary] 核心结论
> MTU 是一条链路的链路层帧一次能够承载的最大网络层数据报长度
> IP 数据报超过下一链路 MTU 时，IPv4 可能分片；
> IPv6 路由器绝不分片，而是通知源主机减小分组
#### MTU 的准确含义
MTU（最大传输单元）限制的是**链路层帧载荷中可承载的网络层数据报大小**，不是整个链路层帧的最大总长度

以普通以太网为例：
- 以太网 MTU 通常为 1500 B，即一个帧通常最多承载 1500 B 的 IP 数据报；
- 以太网首部和 FCS 是链路层自身开销，不计入这 1500 B；
- IPv4 首部、TCP 首部属于这 1500 B 内部的内容。

不同链路可以具有不同 MTU，一条端到端路径上的最小 MTU 称为路径 MTU（PMTU）

#### TCP 分段、IP 分片和链路层成帧

| 操作 | 层次 | 划分对象 | 接收方如何处理 |
| --- | --- | --- | --- |
| TCP 分段 | 运输层 | 应用层字节流 | TCP 按序号重组字节流 |
| IP 分片 | 网络层 | 一个过大的 IP 数据报 | 目的主机 IP 层重组原数据报 |
| 链路层成帧 | 数据链路层 | 一个可由该链路承载的网络层数据报 | 每经过一段链路都重新封装和解封装 |

TCP 主动把数据分成合适的报文段通常比产生 IP 分片更理想，因为任何一个 IP 分片丢失，原始数据报都无法完整重组。

#### MSS 与 MTU
MSS 是 TCP 报文段中**应用数据部分**的最大长度，不包括 TCP 首部和 IP 首部
在没有 IP/TCP 选项的典型情形下：
$$
MSS = MTU - IP\ 首部长度 - TCP\ 首部长度
$$

以 MTU=1500 B 为例：
- IPv4 基本首部 20 B、TCP 基本首部 20 B，典型 MSS 为 1460 B；
- IPv6 基本首部 40 B、TCP 基本首部 20 B，典型 MSS 为 1440 B。

实际路径若包含额外封装、IP 扩展首部或 TCP 选项，可用于数据的空间还会变化

#### IPv4 分片字段

IPv4 使用三个首部字段支持分片：

| 字段  | 作用                       |
| --- | ------------------------ |
| 标识  | 同一原始数据报的所有分片使用相同标识       |
| DF  | DF=1 表示禁止分片              |
| MF  | MF=1 表示后面还有分片，最后一片 MF=0  |
| 片偏移 | 本片数据在原数据部分中的起始位置，单位为 8 B |
重组只由**最终目的主机**完成，中间路由器不会因为下一条链路 MTU 变大就提前重组
#### IPv4 分片计算
设下一链路 MTU 为 $M$，每个分片的 IPv4 首部长度为 $H$。除最后一片外，每片最多携带的数据量为：
$$
L = \left\lfloor\frac{M-H}{8}\right\rfloor \times 8
$$
乘除 8 是因为片偏移以 8 B 为单位。每个分片都拥有自己的 IPv4 首部，因此：
$$
分片总长度 = 分片数据长度 + 分片首部长度
$$
片偏移为：
$$
片偏移 = \frac{本片数据在原数据部分中的起始字节位置}{8}
$$
##### 计算示例
一个 IPv4 数据报总长度为 4000 B，首部为 20 B，需要经过 MTU=1500 B 的链路
原始数据长度：
$$
4000-20=3980\ \mathrm{B}
$$
每个非最后分片最多携带：
$$
\left\lfloor\frac{1500-20}{8}\right\rfloor\times8=1480\ \mathrm{B}
$$

| 分片 | 数据长度 | 总长度 | 片偏移 | MF |
| --- | ---: | ---: | ---: | ---: |
| 第 1 片 | 1480 B | 1500 B | 0 | 1 |
| 第 2 片 | 1480 B | 1500 B | 185 | 1 |
| 第 3 片 | 1020 B | 1040 B | 370 | 0 |

其中第 2 片偏移为 $1480/8=185$，第 3 片偏移为 $(1480+1480)/8=370$。最后一片的数据长度不要求是 8 B 的整数倍
#### 已经分片的数据报还能再次分片
若某个分片仍大于后续链路的 MTU，它还可以被再次分片
新分片：
- 仍使用原数据报的标识值；
- 片偏移仍相对于**最初原始数据部分**计算，而不是相对于被再次切分的分片；
- 只有原始数据报的最后一片所派生出的最后一片才可能令 MF=0。
#### DF 与 ICMP
IPv4 数据报满足以下条件时，路由器不能把它送上下一链路：
- 数据报长度大于下一链路 MTU；
- DF=1，禁止分片

此时路由器丢弃数据报，并通常返回 ICMP Destination Unreachable 中的“需要分片但 DF 已设置”信息，供源主机调整发送大小。
#### IPv6 与路径 MTU 发现
IPv6 路由器不执行分片
分组大于下一链路 MTU 时：
1. 路由器丢弃分组；
2. 向源主机发送 ICMPv6 Packet Too Big，并携带可接受的 MTU；
3. 源主机降低分组大小；
4. 若确实需要 IPv6 分片，只能由源主机加入分片扩展首部。
路径 MTU 发现（PMTUD）的目标是找出整条路径可直接承载的最大 IP 数据报大小，从源头避免路由器分片
若相关 ICMP 报文被错误过滤，可能出现“连接建立成功但较大数据传不过去”的 PMTU 黑洞
#### 分片的代价
- 每个分片都要附加 IP 首部，增加开销；
- 任一分片丢失，整个原始数据报无法完成重组；
- 分片可能乱序到达，需要目的主机缓存；
- 防火墙、NAT 对分片的处理更复杂；
- 所以现代网络更倾向于通过 MSS、PMTUD 和源端合理分段来避免 IP 分片
#### 408 高频易错点
> [!warning] 易错点
> - MTU 通常指最大 IP 数据报长度，不是“最大链路层帧总长度”。
> - IPv4 数据报总长度包含首部；分片题必须先减去原首部求数据长度。
> - 每个分片都有自己的 IP 首部，不能只给第一个分片加首部。
> - 片偏移以 8 B 为单位，除最后一片外，各片数据长度必须是 8 B 的整数倍。
> - 分片在目的主机重组，不在中间路由器重组。
> - IPv6 不是完全不能分片，而是路由器不能分片。
> - MSS 是 TCP 数据长度上限，不包含 TCP/IP 首部；MTU 则包含它们。
