### IPv6
> [!summary] 核心结论
> IPv6 地址长 128 bit，基本首部固定为 40 B
> 它扩大了地址空间并简化路由器的逐包处理：基本首部没有首部校验和，路由器不执行分片，扩展功能由扩展首部承载

#### 基本首部
![[Pasted image 20251021145532.png]]

| 字段 | 长度 | 含义与考点 |
| --- | ---: | --- |
| 版本 | 4 bit | IPv6 中取值为 6 |
| 流量类别 | 8 bit | 用于区分服务和拥塞通知，作用类似 IPv4 的 DS 字段 |
| 流标签 | 20 bit | 标识希望得到一致处理的一条流 |
| 有效载荷长度 | 16 bit | 基本首部之后内容的长度，包括扩展首部和上层数据；不包含 40 B 基本首部 |
| 下一个首部 | 8 bit | 指明紧随其后的扩展首部或上层协议，例如 TCP、UDP、ICMPv6 |
| 跳数限制 | 8 bit | 功能类似 IPv4 的 TTL，每经过一台路由器至少减 1 |
| 源地址 | 128 bit | 源 IPv6 地址 |
| 目的地址 | 128 bit | 目的 IPv6 地址 |
#### 扩展首部链
IPv6 把 IPv4 首部中的选项等可选功能移到基本首部之后。基本首部及每个扩展首部中的“下一个首部”字段共同形成一条链：
```text
IPv6 基本首部
→ 扩展首部（可能有多个）
→ TCP / UDP / ICMPv6 等上层协议
```

因此，“下一个首部”不是存放选项的位置，而是标识**紧随其后的首部类型**

常见扩展首部包括逐跳选项、路由、分片、目的选项、认证首部等。多数中间路由器无须处理全部扩展首部，从而简化普通转发
#### 与 IPv4 的主要区别

| 项目 | IPv4 | IPv6 |
| --- | --- | --- |
| 地址长度 | 32 bit | 128 bit |
| 基本首部 | 20～60 B，可变长 | 固定 40 B |
| 首部校验和 | 有，只检查首部 | 基本首部没有 |
| 分片 | 源主机和路由器都可能执行 | 只有源主机可以执行，使用分片扩展首部 |
| 广播 | 支持 | 不支持，相关功能通常由多播完成 |
| 地址解析 | ARP | ICMPv6 邻居发现协议 NDP |
| 可选功能 | IPv4 选项 | IPv6 扩展首部 |

IPv6 路由器发现分组大于下一链路 MTU 时，丢弃分组并向源主机发送 ICMPv6 Packet Too Big 报文，源主机据此减小分组，详见 [[MTU与IP分片]]

#### 地址表示
IPv6 地址写为 8 组十六进制数，每组 16 bit，用冒号分隔：
```text
2001:0db8:0000:0000:0000:ff00:0042:8329
```

可以使用两条压缩规则：
- 每组前导 0 可以省略：`0db8` 可写为 `db8`；
- 一段或多段连续的全 0 组可以压缩成 `::`，但一个地址中只能使用一次。

上例可压缩为：
```text
2001:db8::ff00:42:8329
```

前缀仍使用 `/p` 表示，例如 `2001:db8:abcd:12::/64`。实际 IPv6 局域网通常使用 `/64`，但“所有 IPv6 网络都必须是 `/64`”并不是普遍成立的地址语法规则

#### 地址类型
IPv6 没有广播地址，主要使用单播、多播和任播
##### 常见单播地址
| 类型    | 前缀或地址          | 用途                         |
| ----- | -------------- | -------------------------- |
| 全球单播  | 通常为 `2000::/3` | 可在全球 IPv6 互联网中路由           |
| 链路本地  | `fe80::/10`    | 只在当前链路有效，路由器不转发；邻居发现等机制依赖它 |
| 唯一本地  | `fc00::/7`     | 供组织内部使用，通常不在全球互联网中路由       |
| 未指明地址 | `::/128`       | 表示尚无可用地址，只能作某些报文的源地址       |
| 回环地址  | `::1/128`      | 本机回环                       |
##### 多播地址
- 前缀为 `ff00::/8`；
- 一个多播地址标识一组接口；
- IPv6 使用多播完成许多 IPv4 中依赖广播的功能
##### 任播地址
- 任播地址在格式上取自单播地址空间，没有单独的特殊前缀；
- 同一地址分配给多个接口，路由系统把分组送往按路由度量看最合适的一个；
- “最近”指路由协议度量最优，不一定是地理距离最近，详见 [[IP任播]]
#### 邻居发现与地址配置
IPv6 不使用 ARP，而使用基于 ICMPv6 的邻居发现协议 NDP，完成：
- 邻居地址解析；
- 路由器发现；
- 前缀发现；
- 邻居可达性检测；
- 重复地址检测

IPv6 主机可以通过 SLAAC 根据路由器通告自动配置地址，也可以使用 DHCPv6
SLAAC、DHCPv6 与是否获得默认路由不能简单视为完全相同的流程
#### IPv4 向 IPv6 过渡

| 方法 | 思路 |
| --- | --- |
| 双协议栈 | 设备同时运行 IPv4 和 IPv6，根据目的地址与网络能力选择协议 |
| 隧道 | 把 IPv6 数据报封装在 IPv4 数据报中穿越仅支持 IPv4 的网络，隧道两端再封装与解封装 |
| 翻译 | 在 IPv4 与 IPv6 报文之间转换，例如 NAT64 配合 DNS64 |

408 教材最常强调双协议栈和隧道
隧道封装后，外层 IPv4 源、目的地址是隧道端点，内层 IPv6 源、目的地址仍是原始通信端点

#### 408 高频易错点
> [!warning] 易错点
> - IPv6 基本首部固定 40 B，但不等于整个 IPv6 首部链永远只有 40 B。
> - 有效载荷长度不包含 40 B 基本首部，却包含扩展首部。
> - IPv6 不是“不能分片”，而是**路由器不能分片，源主机可以借助分片扩展首部分片**。
> - IPv6 没有广播，但有多播和任播。
> - IPv6 基本首部没有首部校验和，不表示上层数据完全没有差错检测。
> - 下一个首部既可能指向扩展首部，也可能直接指向 TCP、UDP、ICMPv6 等上层协议。
