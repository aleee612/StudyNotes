> NAT 位于网络边界，在报文经过时修改 IP 地址；常见的 NAPT/PAT 还会修改端口号，使多台私网主机共享少量公网 IPv4 地址。

### 公有地址与私有地址
IPv4 私有地址范围：

| 范围 | 前缀 |
| --- | --- |
| `10.0.0.0～10.255.255.255` | `10.0.0.0/8` |
| `172.16.0.0～172.31.255.255` | `172.16.0.0/12` |
| `192.168.0.0～192.168.255.255` | `192.168.0.0/16` |

- 私有地址只在相应私网中有意义，公共互联网路由器通常不转发这些前缀。
- 公有地址可在公共互联网中路由，但仍取决于运营商和路由策略。
- 公有或私有与“是否写 `/前缀长度`”无关；任何 IP 网络都可以用 CIDR 前缀表示。
- LAN/WAN 描述网络覆盖范围，公有/私有描述地址的可路由范围，二者不是同一分类维度。

### NAT 的主要作用

- 让使用私有 IPv4 地址的内部主机访问公共互联网；
- 让多台内部主机共享一个或少量公网地址，缓解 IPv4 地址不足；
- 隐藏内部地址结构，但 NAT 本身不等于防火墙或完整的安全机制。

### 基本 NAT
基本 NAT 只转换 IP 地址，建立私有地址和公网地址之间的映射：

```text
内部本地地址  ←→  内部全局地址
```

它通常需要可用公网地址池，不能仅靠一个公网地址同时区分大量并发内部主机。

### NAPT / PAT

家庭路由器常用的其实是网络地址端口转换：

```text
私网源 IP:源端口
        ↓ NAT
公网 IP:转换后端口
```

返回报文到达后，NAT 根据转换表恢复对应的私网目的 IP 和端口。

> [!example]
> 两台内部主机都可以使用源端口 5000：
>
> - `192.168.1.10:5000` → `203.0.113.8:40001`
> - `192.168.1.20:5000` → `203.0.113.8:40002`
>
> NAT 用不同的外部端口及协议、地址等表项区分连接，并不要求所有内部主机使用不同源端口。

### NAT 转换表

实际表项通常会结合：

- 运输层协议；
- 内部地址与端口；
- 转换后的外部地址与端口；
- 对端地址与端口或连接状态；
- 超时时间。

> 因此不能把 NAT 表简单理解成只有“一个 IP 加一个端口”。具体字段取决于 NAT 类型和实现

### 公网地址的来源

NAT 设备的公网地址可能通过以下方式获得：

- DHCP；
- PPP/PPPoE 等接入过程；
- 静态配置；
- 运营商的其他地址分配机制。

> 所以“NAT 路由器的公网地址一定由 DHCP 获得”不成立。

### 入站连接与端口映射

内网主机主动建立连接时，NAT 可以根据出站报文自动创建映射；公共网络主动访问内网主机时，通常没有现成表项，需要：

- 静态 NAT；
- 端口转发；
- UPnP/PCP 等映射机制；
- 应用层中继、打洞或其他 NAT 穿越技术。

### NAT 的问题
- 修改网络层地址，NAPT 还检查和修改运输层端口，削弱了端到端原则；
- 外部主机难以主动连接内部主机；
- 某些在载荷中携带 IP 地址或端口的协议需要应用层网关协助；
- 转换设备需要维护状态，重启或故障可能中断现有映射；
- 多层 NAT 和运营商级 NAT 会增加定位与入站连接的复杂度。

### NAT 与其他概念的区别

| 概念 | 主要作用 |
| --- | --- |
| [[DHCP]] | 自动给主机配置 IP、掩码、网关、DNS 等参数 |
| [[子网划分与路由聚合]] | 划分地址空间、表示前缀并聚合路由 |
| NAT/NAPT | 在网络边界转换地址或端口 |
| 路由 | 根据目的网络前缀选择下一跳 |

#### 高频易错点
1. NAT 的主要目的不是“让两个私网相互通信”，而是地址转换和公网访问。
2. NAT 不等于 DHCP；公网地址也不一定由 DHCP 获得。
3. 公有、私有地址都能写 `/前缀长度`。
4. 两台内网主机可以使用相同源端口，NAPT 会分配不同外部映射。
5. NAT 提供一定的地址隐藏效果，但不能替代防火墙。
6. NAT 转换的是经过边界设备的报文；同一局域网内主机直接通信通常不经过 NAT。
