### IP多播/组播
> 让源主机一次发送的单个分组可以抵达用一个组地址表示的若干目的主机
> 即发送时的IP：主机=1：n

![[Pasted image 20260312114551.png]]

| 组成 | 作用 |
| --- | --- |
| 组播地址 | 标识一组接收接口，IPv4 使用 D 类地址 |
| IGMP | 管理主机与本地多播路由器之间的组成员关系 |
| 组播路由协议 | 在路由器之间建立和维护组播转发路径 |

> [!summary]
> IP 组播 = 组地址 + 本地成员管理（IGMP）+ 组播路由转发。IGMP 不负责计算整个互联网中的组播路由。

---
### IP多播地址
| 地址类型 | 地址内容              |
| ---- | ----------------- |
| 源地址  | 源主机 IP            |
| 目的地址 | IP多播地址（IPv4的D类地址） |
多播地址范围：224.0.0.0 ~ 239.255.255.255
#### 协议字段值
UDP：17
IGMP：2
注意事项：
1. IP 多播本身是尽力而为交付；传统 TCP 是点到点连接，不能直接建立“一条 TCP 连接对整个多播组”的传输。多播应用常使用 UDP 或专门的可靠多播机制
2. 只能用于目的地址
3. 不产生ICMP差错报文
#### 分类
1. 只在本局域网上进行硬件多播
2. 在互联网的范围内进行多播
### 硬件多播
> 将IP多播地址映射为对应的**多播 MAC 地址** 
#### 地址范围
`01-00-5E-00-00-00` ~ `01-00-5E-7F-FF-FF`
- 仅后23位用于多播
- 多播IP ：多播MAC = n : 1
### IGMP 网际组管理协议
> 使连接到本地局域网的**多播路由器**能获知本局域网上是否有主机加入、退出某多播组
#### 注意事项
1. 仅作用于本地子网
2. 既不知道某个多播组的总成员数量，也不了解这些成员分布在哪些网络
3. 封装在 IP 数据报中
4. IGMP被视为是整个IP协议的一个组成部分而非一个单独协议
#### 工作流程
1. 新加入主机向该多播组的多播路由器发送一个IGMP报文
	- 目的地址：多播IP地址
2. 本地多播路由器据此维护“该接口是否存在该组接收者”的状态；组播路由协议再利用成员状态和网络拓扑建立分发树，但并非简单地把每条 IGMP 报文逐路由器转发
3. 多播路由器周期性查询本地局域网上的主机，以探测各多播组是否仍有活跃成员
	- 只要有一个主机回应就认为本网络仍处于活跃状态
	- 若多次查询后仍无主机回应则认为该接口已无该组成员，并可停止向该接口转发对应组流量
