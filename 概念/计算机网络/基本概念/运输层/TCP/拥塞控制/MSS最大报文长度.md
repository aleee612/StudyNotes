### MSS 最大报文段长度

> [!summary] 核心结论
> MSS 限制一个 TCP 报文段中 TCP 数据部分的最大长度，不包含 TCP 首部和 IP 首部。连接双方在 SYN 报文中分别通告自己愿意接收的 MSS，它不是双方协商出一个对称的共同值。

#### MSS 的含义

- MSS 属于 TCP 概念，单位是字节；
- 它只限制 TCP 报文段的数据部分；
- 发送方向对端发送数据时，应受**对端通告的 MSS**约束；
- 两个方向的 MSS 可以不同。

#### MSS 通告

TCP 建立连接时，双方可以在各自的 SYN 报文 TCP 选项中携带 MSS：

- A 通告的 MSS 表示 A 愿意接收的最大 TCP 数据长度，约束 B→A；
- B 通告的 MSS 表示 B 愿意接收的最大 TCP 数据长度，约束 A→B；
- 若 SYN 中没有 MSS 选项，则采用协议规定的默认值，而不是无限制发送。

因此，“实际 MSS 一律取双方数值的较小值”只是一种过度简化。协议上它是**单向通告**，发送端还会结合路径 MTU、拥塞窗口、接收窗口和实现策略决定实际报文段大小。

#### 与 MTU 的关系

为避免 IP 分片，MSS 常按可用 MTU 扣除 IP 和 TCP 首部估算：

$$
MSS = MTU - IP\ 首部长度 - TCP\ 首部长度
$$

在普通以太网 MTU=1500 B 且无额外选项时：

- IPv4：$1500-20-20=1460$ B；
- IPv6：$1500-40-20=1440$ B。

完整关系和分片计算见 [[MTU与IP分片]]。

#### 与窗口和拥塞控制的关系

- 接收窗口和拥塞窗口都以字节表示，不以“报文段个数”表示；
- 慢启动、拥塞避免等算法经常用 MSS 表示窗口增减幅度；
- 一次实际发送的数据量还同时受 MSS、接收窗口、拥塞窗口和待发送数据量限制。

#### 408 高频易错点

> [!warning] 易错点
> - MSS 不包含 TCP/IP 首部，MTU 包含它们。
> - MSS 在 SYN 中通告，不是“双方协商出同一个值”。
> - MSS 是接收能力的单向声明，两个方向可能不同。
> - MSS 主要帮助源端合理分段、避免 IP 分片；它不保证路径中永远不会出现更小 MTU。
